Apache Iceberg™ v3 — What's New
The next-generation spec, co-authored by Snowflake, available in Snowflake today.
Iceberg v3 is a major leap in the open table format spec — richer data types, faster deletes, better schema evolution, and row lineage for audit trails. Snowflake co-authored v3 and was one of the first platforms to ship full support.
Spec Version
v3
Apache Iceberg™
Variant & Structured Type
Store semi-structured JSON natively in an Iceberg column. Variant type aligns Iceberg with Snowflake's native VARIANT, making it possible to share semi-structured data across engines without serialization tricks.
New Type
Deletion Vectors
Instead of rewriting entire data files on DELETE or UPDATE, v3 writes a small bitmap sidecar file marking deleted rows. This dramatically reduces write amplification for high-frequency DML workloads.
Faster Writes
Row Lineage & Provenance
Every row carries a unique identifier and commit sequence number. Engines can trace exactly when and where a row was written — enabling detailed audit trails and change data capture without separate CDC pipelines.
New Capability
Default Column Values
Schema evolution now supports declaring default values for new columns. Older files that predate the column still return the correct default — no backfill scans, no null-handling workarounds across engines.
Schema Evolution
Improved Merge-on-Read
v3 formalizes the merge-on-read (MoR) path with deletion vectors as the preferred delete mechanism. Combined with improved read planning, readers like Snowflake apply row-level deletes at query time with minimal overhead.
Query Performance
Stable, Backward-Compatible Spec
v3 tables remain fully readable by v2-compatible engines (v3 is a superset of v2). Existing v2 tables can opt in to v3 features incrementally — no forced migrations or compatibility breaks.
Compatibility
Snowflake co-authored Iceberg v3 and is a founding member of Apache Polaris™ (incubating) — the open-source REST catalog that implements the Iceberg catalog spec and powers multi-engine interoperability without vendor lock-in.
