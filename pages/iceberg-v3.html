Apache Iceberg™ v3 — What's New
The next-generation spec, co-authored by Snowflake, available in Snowflake today.
Iceberg v3 is a major leap in the open table format spec — richer data types, faster deletes, better schema evolution, and row lineage for audit trails. Snowflake co-authored v3 and was one of the first platforms to ship full support.
Spec Version
v3
Apache Iceberg™
Variant Support
Fast, flexible semi-structured data. Store semi-structured JSON natively in an Iceberg column, aligned with Snowflake's native VARIANT type for seamless cross-engine sharing.
New Type
Geospatial
Geometry and Geography types. Native geospatial type support in the Iceberg spec enables portable spatial data across engines without proprietary extensions.
New Type
Row Lineage
Efficient CDC and incremental processing. Every row carries a unique identifier and commit sequence number for detailed audit trails and change data capture without separate pipelines.
New Capability
Nanosecond Timestamp
More precise timestamps. v3 extends timestamp precision to nanoseconds, enabling high-frequency event data and time-series workloads that require sub-microsecond resolution.
Precision
Deletion Vectors
More efficient row-level deletes – read-only. Instead of rewriting data files on DELETE or UPDATE, v3 writes a small bitmap sidecar marking deleted rows, dramatically reducing write amplification.
Faster Writes
Default Values
Column-level defaults. Schema evolution now supports default values for new columns — older files return the correct default without backfill scans or null-handling workarounds.
Schema Evolution
Snowflake co-authored Iceberg v3 and is a founding member of Apache Polaris™ (incubating) — the open-source REST catalog that implements the Iceberg catalog spec and powers multi-engine interoperability without vendor lock-in. 
CREATE OR REPLACE ICEBERG TABLE my_iceberg_v3_table (
    boolean_col  boolean,
    int_col      int,
    long_col     long
  )
  CATALOG='my_catalog_integration'
  ICEBERG_VERSION=3;
Create an Iceberg v3 table by setting ICEBERG_VERSION=3. The CATALOG parameter points to an existing catalog integration. v3 unlocks Variant, Geospatial, Row Lineage, Deletion Vectors, Nanosecond Timestamps, and Default Values.
