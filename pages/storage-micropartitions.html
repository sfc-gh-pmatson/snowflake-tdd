Storage Architecture
Micro-Partitioning
Every Snowflake table is automatically divided into immutable, compressed micro-partitions — no tuning, no index design, no manual maintenance.
Immutable Columnar Storage
Data is stored in 50–500 MB compressed columnar files. DML never overwrites a partition — updates and deletes create new partitions, making the old versions available for Time Travel. No fragmentation, no vacuum, no index rebuild.
Rich Column-Level Metadata
For every column in every micro-partition, Snowflake stores: min/max values, distinct count, null count, and a bloom filter. This metadata lives in the Cloud Services layer — no table scan required to determine partition relevance.
Partition Pruning
Before any scan, Snowflake compares query predicates against partition metadata. Partitions whose min/max range cannot contain matching rows are skipped entirely. In well-ordered tables, 80–99% of partitions can be pruned — dramatically reducing I/O and compute cost.
Time Travel & Fail-Safe
Because partitions are never overwritten, Snowflake retains previous versions automatically. AT(TIMESTAMP => ...) or BEFORE(STATEMENT => ...) queries the table as it was. Fail-Safe extends protection 7 days beyond the Time Travel window for disaster recovery.
