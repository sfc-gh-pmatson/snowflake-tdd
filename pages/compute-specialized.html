Adaptive Warehouses
Auto-tunes for mixed workloads without manual resizing
QUERY_THROUGHPUT_MULTIPLIER (1–3×) boosts parallel query throughput within the same warehouse
MAX_QUERY_PERFORMANCE_LEVEL (1–10) caps resources allocated to a single query — prevents one query from starving others
Automatically selected as the default warehouse type. No migration required for new warehouses.
Ideal for mixed BI + ad-hoc workloads where query complexity varies widely.
Upgrade from Gen1: check with SHOW WAREHOUSES — the type column shows generation. Recreate existing warehouses to get Gen2. All new warehouses are Gen2 by default.
Serverless Offload
Query Acceleration Service
Offloads large scan portions to serverless compute on demand
Large scans offloaded to Snowflake-managed serverless compute — warehouse stays available for other queries
QUERY_ACCELERATION_MAX_SCALE_FACTOR caps how many serverless credits a query can consume (default: 8)
Eligible queries automatically detected — no per-query configuration. Billed per QAS credit-second on top of warehouse credits.
Best for: dashboards with unpredictable large scan queries, exploratory analytics, long-tail query patterns.
ML & Python
Snowpark-Optimized
16× memory-to-compute ratio for memory-intensive workloads
Standard warehouses have a fixed compute-to-memory ratio. Snowpark-Optimized provides 16× more memory per node — critical for ML model training.
Created with WAREHOUSE_TYPE = SNOWPARK-OPTIMIZED
Required for: PyTorch / XGBoost training on large datasets, heavy Snowpark Python UDFs, ML feature engineering with large in-memory objects.
Separate from standard warehouses — dedicate one warehouse to ML workloads, keep BI on standard.
