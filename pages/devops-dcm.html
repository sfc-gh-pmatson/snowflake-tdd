Database Change Management
Declarative schema management for Snowflake — define your database objects as code, deploy with confidence, and eliminate drift between environments.
Imperative (Traditional)
Manual SQL scripts per environment — easy to drift
Ordered migration files with no conflict detection
Roles and grants managed separately — often forgotten
No preview — changes go straight to production
→
Declarative (DCM)
Desired state in manifest.yml — DCM diffs & applies
Order-independent: add or remove objects freely
Roles auto-generated: ADMIN / READ-WRITE / READ-ONLY per schema
snow dcm plan previews every change before deploy
DEFINE Objects
Declare tables, views, schemas, and databases in a versioned YAML manifest. DCM computes the delta and applies only what changed.
DEFINE TABLE DEFINE SCHEMA manifest.yml
Auto-Generated Roles
DCM generates three roles per schema automatically — ADMIN, READ-WRITE, and READ-ONLY — following the Snowflake three-tier access pattern with correct grants applied.
ADMIN role RW role RO role
CI/CD Deployment
Use snow dcm plan to preview the changeset and snow dcm deploy to apply it. Drop into any GitHub Actions or GitLab CI pipeline.
snow dcm plan snow dcm deploy GitHub Actions
