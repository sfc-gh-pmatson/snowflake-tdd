-- Snowflake-managed Iceberg on your S3 bucket
CREATE OR REPLACE ICEBERG TABLE customer_events
  EXTERNAL_VOLUME = 'my_s3_volume'
  CATALOG = 'SNOWFLAKE'
  BASE_LOCATION = 'customer_events/';

-- Full Snowflake performance on your storage
SELECT region, COUNT(*) AS events
FROM customer_events
WHERE event_date >= '2025-01-01'
GROUP BY region;

-- Governance applied — same engine that wrote it
CREATE ROW ACCESS POLICY region_policy
  AS (region STRING) RETURNS BOOLEAN ->
    current_role() = 'ADMIN'
    OR region = current_user_region();

ALTER TABLE customer_events
  ADD ROW ACCESS POLICY region_policy
  ON (region);

Iceberg on Your Storage

The table lives in your S3 bucket as Parquet + Iceberg metadata. Snowflake manages the catalog, compaction, and query optimization.

Any engine can read it. Spark, Flink, Dremio, and Trino all access the same files via the Iceberg REST catalog endpoint Snowflake exposes.

Row access policies, masking policies, and RBAC apply to every reader — not just Snowflake queries.
