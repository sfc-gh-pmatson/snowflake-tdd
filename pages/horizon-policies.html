Data Protection Policies
Apply masking, filtering, and access controls inline — enforced automatically on every query.
Column-Level Policy
Masking Policies
Replace sensitive column values with masked equivalents based on the querying role.
🔒
Role-Based Masking
Define masking logic in SQL: full mask (return null/stars), partial mask (show last 4 digits), or hash. Different roles see different representations of the same column.
🏷
Tag-Based Inheritance
Bind a masking policy to a tag. Every column tagged with that tag automatically gets masked — no per-column assignment needed.
-- Create a masking policy
CREATE MASKING POLICY mask_email
  AS (val STRING) RETURNS STRING
  -> CASE
    WHEN CURRENT_ROLE() IN ('ADMIN') THEN val
    WHEN CURRENT_ROLE() IN ('ANALYST')
      THEN '***@' || SPLIT_PART(val,'@',2)
    ELSE '*****'
  END;

-- Apply to a column
ALTER TABLE customers
  MODIFY COLUMN email
  SET MASKING POLICY mask_email;
Row-Level Policy
Row Access Policies
Filter which rows a role can see — based on a policy mapping table, with no query changes required.
☰
Policy Mapping Table
A separate table maps roles (or users) to the allowed values of a filter column (region, department, cost center). Policy joins this table at query time.
👁
Transparent to Users
Users run SELECT * FROM sales and only see rows they\'re allowed to see. The policy is invisible and cannot be bypassed.
-- Create row access policy
CREATE ROW ACCESS POLICY region_filter
  AS (region STRING)
  RETURNS BOOLEAN
  -> region IN (
    SELECT allowed_region
    FROM access_map
    WHERE role_name = CURRENT_ROLE()
  );

-- Apply to table
ALTER TABLE sales
  ADD ROW ACCESS POLICY region_filter
  ON (region);
Column-Level Policy
Projection Policies
Prevent a column from being SELECTed directly — filter on it, but never export its values.
🚫
Visible but Unexportable
Column appears in schema and can be used in WHERE clauses. But it cannot appear in SELECT results. Perfect for: “analysts can filter by SSN but never see the actual value.”
⛵
Complements Masking
Use projection policies when full masking isn\'t enough — you want to prevent a column from appearing in any result set, not just mask its value.
-- Create projection policy
CREATE PROJECTION POLICY no_ssn_export
  AS () RETURNS PROJECTION_CONSTRAINT
  -> CASE
    WHEN CURRENT_ROLE() = 'ADMIN'
      THEN PROJECTION_CONSTRAINT(ALLOW => true)
    ELSE PROJECTION_CONSTRAINT(ALLOW => false)
  END;

ALTER TABLE customers
  MODIFY COLUMN ssn
  SET PROJECTION POLICY no_ssn_export;
Column-Level Policy
Aggregation Policies
Require aggregation on sensitive columns — prevent row-level exposure by enforcing minimum group sizes.
Σ
Enforce Minimum Group Size
Queries on a protected column must aggregate results. MIN_GROUP_SIZE prevents re-identification — if a group has fewer rows than the minimum, the query is blocked.
📊
Statistical Privacy
Used in healthcare, finance, and research settings where individual row values must never be exposed even through aggregation-based re-identification attacks.
-- Create aggregation policy
CREATE AGGREGATION POLICY min_group_5
  AS () RETURNS AGGREGATION_CONSTRAINT
  -> CASE
    WHEN CURRENT_ROLE() = 'ANALYST'
      THEN AGGREGATION_CONSTRAINT(
        MIN_GROUP_SIZE => 5)
    ELSE NO_AGGREGATION_CONSTRAINT()
  END;

ALTER TABLE health_records
  SET AGGREGATION POLICY min_group_5;
Column-Level Policy
Tokenization
Replace sensitive values with tokens via an external vault — data stays usable but original values are protected.
🔑
External Vault Integration
Tokenization uses an external tokenization vault (e.g., Protegrity, Voltage) via a Snowflake External Function. The vault maps token ↔ original value. Snowflake stores only the token.
🔄
Reversible with Authorization
Authorized roles can de-tokenize by calling the vault. Unauthorized roles always see the token — the original value never leaves the vault without explicit permission.
-- Tokenization via masking policy + external fn
CREATE MASKING POLICY tokenize_cc
  AS (val STRING) RETURNS STRING
  -> CASE
    WHEN CURRENT_ROLE() = 'PAYMENT_ADMIN'
      THEN val
    ELSE
      my_tokenize_udf(val)
  END;

ALTER TABLE payments
  MODIFY COLUMN card_number
  SET MASKING POLICY tokenize_cc;
