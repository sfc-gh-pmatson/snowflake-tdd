Access Control
One security model across all data — roles, network, identity, and encryption.
Role-Based
RBAC
Hierarchical privilege model for all Snowflake objects
Every operation requires a privilege. Roles are granted to users and other roles. Column-level, row-level, and object-level access all controlled through one model.
GRANT SELECT ON TABLE orders
  TO ROLE analyst_role;
Network
Network Policies
Restrict connections by IP address or CIDR range
Allowlist and denylist by IP range. Attach at account level or per-user. Blocks all connections from unauthorized networks before authentication.
CREATE NETWORK POLICY corp_only
  ALLOWED_IP_LIST = ('10.0.0.0/8');
Identity
MFA
Enforce multi-factor authentication via policy
Authentication Policies enforce MFA for all users, specific roles, or specific client types. TOTP-based. Also controls allowed authentication methods (password, keypair, SSO, OAuth).
CREATE AUTHENTICATION POLICY require_mfa
  MFA_ENROLLMENT = REQUIRED;
Identity
SSO / SAML
Federated identity via SAML 2.0 with any IdP
Integrate with Okta, Azure AD, Ping Identity, OneLogin. JIT user provisioning. No password sync. Same session as corporate IdP — revoke at the IdP to immediately cut access.
CREATE SECURITY INTEGRATION okta_sso
  TYPE = SAML2
  SAML2_ISSUER = 'https://okta.com/...';
Encryption
Tri-Secret Secure
Customer-managed encryption key via cloud KMS
Your KMS key + Snowflake key = both required to decrypt. Supports AWS KMS, Azure Key Vault, GCP KMS. Revoke your key and data is immediately inaccessible — even to Snowflake employees.
-- Configured via account-level setting
-- + KMS integration in your cloud console
ALTER ACCOUNT SET
  TRI_SECRET_SECURE = TRUE;
Identity
OAuth
Delegated access for BI tools and custom apps
OAuth 2.0 for Tableau, Power BI, Streamlit, and custom integrations. Users authenticate via their IdP; tools receive a scoped access token. No credential embedding in BI configs.
CREATE SECURITY INTEGRATION tableau_oauth
  TYPE = OAUTH
  OAUTH_CLIENT = TABLEAU_DESKTOP;
