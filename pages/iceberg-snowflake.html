-- Step 1: Create an external volume pointing to your cloud storage
CREATE OR REPLACE EXTERNAL VOLUME my_iceberg_vol
  STORAGE_LOCATIONS = (
    (
      NAME                  = 'us-west-2-s3'
      STORAGE_PROVIDER      = 'S3'
      STORAGE_BASE_URL      = 's3://my-bucket/iceberg/'
      STORAGE_AWS_ROLE_ARN  = 'arn:aws:iam::123456:role/my-sf-role'
    )
  );

-- Step 2: Create a Snowflake-managed Iceberg table
CREATE OR REPLACE ICEBERG TABLE my_db.my_schema.events (
  event_id   BIGINT
, event_ts   TIMESTAMP_NTZ
, user_id    STRING
, payload    VARIANT
)
  CATALOG         = 'SNOWFLAKE'
  EXTERNAL_VOLUME = 'my_iceberg_vol'
  BASE_LOCATION   = 'events/';

-- External engines connect via the Snowflake REST catalog endpoint
-- e.g. for Spark:
-- spark.sql.catalog.snowflake = org.apache.iceberg.spark.SparkCatalog
-- spark.sql.catalog.snowflake.catalog-impl = ...SnowflakeCatalog
-- spark.sql.catalog.snowflake.uri = https://<account>.snowflakecomputing.com/polaris/api/catalog

External Volume

An EXTERNAL VOLUME tells Snowflake where in cloud object storage to write Iceberg data files. Snowflake assumes an IAM role (AWS), service principal (Azure), or service account (GCP) to access that location.

Snowflake-Managed Iceberg Table

Setting CATALOG = 'SNOWFLAKE' means Snowflake owns and manages the Iceberg metadata. This enables Time Travel, Fail-safe, automatic compaction, and full query optimization.

External Engine Access

Configure Spark (or another engine) to use Snowflake's Polaris-compatible REST catalog endpoint. External engines read and write the same Parquet/Iceberg files — Snowflake coordinates concurrent access.
