-- Step 1: Create a catalog integration pointing to your external catalog
CREATE OR REPLACE CATALOG INTEGRATION my_unity_catalog
  CATALOG_SOURCE = ICEBERG_REST
  TABLE_FORMAT   = ICEBERG
  CATALOG_NAMESPACE = 'main'
  REST_CONFIG = (
    CATALOG_URI      = 'https://<unity-catalog-endpoint>'
    WAREHOUSE        = '<databricks-warehouse-id>'
  )
  REST_AUTHENTICATION = (
    TYPE = OAUTH
    OAUTH_TOKEN_URI    = 'https://<token-endpoint>/oidc/v1/token'
    OAUTH_CLIENT_ID    = '<client-id>'
    OAUTH_CLIENT_SECRET = '<client-secret>'
  )
  ENABLED = TRUE;

-- Step 2: Create the catalog-linked database
CREATE OR REPLACE DATABASE my_unity_db
  FROM CATALOG INTEGRATION my_unity_catalog;

-- Step 3: Query Iceberg tables directly — no ETL needed
SELECT *
FROM my_unity_db.main.customer_events
LIMIT 100;

Catalog Integration

A CATALOG INTEGRATION tells Snowflake how to authenticate and connect to an external Iceberg catalog that implements the REST catalog spec (e.g., Unity Catalog, Polaris, AWS Glue).

Catalog-Linked Database

CREATE DATABASE ... FROM CATALOG INTEGRATION mounts the external catalog as a native Snowflake database. Tables are auto-discovered — no manual CREATE EXTERNAL TABLE statements needed.

Zero-Copy Querying

Snowflake reads Parquet files directly from the original cloud object storage. Data never moves. Snowflake Horizon governance (masking, row access, RBAC) applies to every query.
